# D1 验收口径 v2（2026-10-26）

## 决定与依据

用户在看到原始随机试验结果及矛盾说明后，要求开发者自行决策并写明说明。本次只校正测试的推论和门槛，不给游戏添加强制进度，不剥夺休息选项，不隐藏原始失败。

原设计同时允许任意天数休息、重复采集，又要求任意分派都保证60天通关。无限休息是合法反例，因此有限随机样本不能证明“任意玩法必定通关”。200个纯随机种子原门槛实测115个完成；85个尚未完成均有有限通关路径，另用目标策略1–5天全部完成。原始报告保留 passed:false。

随机局面中材料丰富仍未点到关键专长动作，说明“完成时间”与“是否死锁”不能混称。目标12天、每天只派一人的慢玩31天，符合正常流程目标。固定目标策略挡住暴雨100%，不能凭一个确定路线代表玩家选择分布。

## 硬门槛

1. 规则/内容/资源/存档/界面回归通过；任何测试失败不能被模拟指标掩盖。
2. 三资源免费来源可达、余额不负，临时洪水有终点；事件过期不永久封锁主线。
3. 200个均匀随机轨迹逐步安全性无失败；所有采样未完成终态均须有明确恢复通关轨迹。报告称“采样验证”，不称无限状态空间的数学证明。
4. 目标导向10–14天且无白过；单人慢玩≤40天。
5. 人工从标题走到结尾，并测试真实拖拽、取消、退款、存档继续、失败反馈和自由玩。
6. 可视截图检查无遮挡、溢出；D1灰盒仍需清晰，不冒充最终美术。

## 保留为诊断项

- 均匀随机200局/60天的完成率、白过比例、新鲜事覆盖、暴雨完成/过期比例。
- 另做固定权重的“探索式随机”模拟可见提示对行为的影响，单独命名、独立报告，不能取代或改写均匀随机结果。
- 如扩大到180天，同样单独报告，不把它叫做通过60天原门槛。
- “目标推进”包括实际增加的水轮/筑坝进度；满值无变化不计。普通重复往事不冒充新事件。

## 流程

D1在上述硬门槛和人工验证结束前仍未验收，不开启D2。npm run check负责静态/回归；npm run sim负责v2完整验收并同时打印原始口径指标。每份报告记录口径、源哈希和失败种子。
